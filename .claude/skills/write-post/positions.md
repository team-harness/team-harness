# 已立的观点与术语

所有文章共享一个论证体系。写新文章前对照这里：已定义的术语直接用并链接过去，不重新解释；新主张和这里矛盾时，**不要悄悄绕开，明确问用户「观点变了吗」**——变了的话，讨论旧文要不要注记，这里也要更新。

格式：一句话主张 + 出处。出处用 `/blog/<slug>#section-N`。

## 核心判断

- **收益是租来的，不是攒下的**——快来自模型本身，人组织工作的方式没变，模型升级红利就不沉淀。（[/blog/intro](/blog/intro) 开场）
- **语言和框架正在变成新的汇编，但类比只成立一半**：编译器的翻译确定，LLM 的翻译是概率性的，且出错的样子和正确时很像。所以「抽象层上移」成立，「彻底不看下一层」不成立。（[/blog/intro#section-1](/blog/intro#section-1)）
  - 整套体系的前提就在这：**正因为翻译不确定，才需要人在关键点放行**。哪天翻译像编译器一样确定了，Harness 就不需要了。
- **Agent 越快，工程规范越必要**。规范没过时，换了执行者：从「希望大家遵守」变成「每次都执行」。（[/blog/intro#section-2](/blog/intro#section-2)）
  - 换执行者也换失效方式：**人的失效是不遵守，Agent 的失效是看起来遵守了**。怎么暴露后者是核心课题。
- **人的新位置是 Gate**：不全程在场，在特定节点做有后果的判断。目标不是让人少被打扰——「少打扰」当指标会让 Agent 在该问时闭嘴——**是降低人做单次判断的难度**。（[/blog/intro#section-3](/blog/intro#section-3)）
- **四层相乘不相加**，最弱的一层决定整体能到哪。（[/blog/intro#section-4](/blog/intro#section-4)）
- **thin harness / 薄约束、厚上下文**：只写稳定明确能判定的约束，实现交给模型推理；但项目上下文不能薄。约束是命令式的会随模型变强而贬值，上下文是描述式的会随仓库变化而过期——治理方式不同。（[/blog/intro#section-6](/blog/intro#section-6)）
- **上下文是交付物**。人向 Agent 的发问，就是需求最原始的样子。摘要服务当前 gate，完整底稿服务交接与追溯，两者不矛盾。（[/blog/intro#section-7](/blog/intro#section-7)）
- **交付环境要面向 Agent**：控制台为人的手和眼设计，不能当正式交付接口。（[/blog/intro#section-8](/blog/intro#section-8)）
- **工具可替换，主张不能缺**。Paseo、Licell 都明说可以被换掉，站得住的是那条要求本身。（贯穿全文）
- **完整 Harness 不是默认配置**。三个该上的信号：一个人记不住所有并行任务的状态；任务开始在人与人之间接力；产出反复进真实生产环境。没有这些问题不必提前造。（[/blog/intro#section-10](/blog/intro#section-10)）

## 术语表

第一次在某篇里出现时可以一句话带过并链接到定义处，不整段重讲。

- **Gate**：从 CI 质量门禁借来的词。人不全程在场，只在特定节点做有后果的判断：放行、拦截、纠偏、补信息。
- **Harness / thin harness**：装工程规范约束的那层东西 / 只写能判定的边界、把怎么做交给模型的约束风格。
- **薄约束、厚上下文**：一对，总是一起出现。
- **底稿**：完整的 Agent 对话时间线，平时不读，有疑点时沿时间线查回去。与 gate 现场的摘要相对。
- **Anywhere**：人的决策入口不绑设备 + Agent 的任务不绑主机，两个解耦。
- **fresh reviewer**：不继承实现者推理过程的新会话审查者；异构模型是加强项不是前提。
- **blocking / important / nit**：审查结果三级，blocking 不清零不许宣称通过。
- **lesson 三态**：observed → validated → retired，不许同任务自我晋级，退役不许复活。
